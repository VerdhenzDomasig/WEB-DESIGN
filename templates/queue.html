    QUICK NOTES

    A waiting line, in code.

    Enqueue adds an item at the rear.

    Dequeue removes the item at the front.

    Peek reads the front without removing it.

    Enqueue A, B, C → dequeue returns A → remaining: B, C.

    Used in waiting lines, print jobs, and breadth-first search.

    End operations take O(1) time with linked nodes. The {{ max_items }}-item limit is for this visual demo.

    A QUICK GUIDE

    Basic information

    A queue is a first-in, first-out (FIFO) collection: items leave in the order they arrive. [1]

    Operations and endpoints

    • Front: the next item to leave.
    • Rear: where a new item joins.
    • Enqueue: add at the rear.
    • Dequeue: remove and return the front.
    • Peek: read the front without removing it.

    Example and uses

    Enqueue A, then B, then CFront → A, B, C ← RearDequeue returns AFront → B, C ← Rear

    Useful for waiting lines, print jobs, and breadth-first search.

    How this demo works

    The Python implementation maintains links to both ends. Enqueue, dequeue, and peek use O(1) endpoint operations. [2]

    Passing state to the server and drawing all items adds O(n) work to the complete UI request.

    Input and empty states

    The visual demo allows 12 items, with up to 32 characters each. Text, numbers, and duplicates are accepted.

    Removing or peeking from an empty queue displays an error. Clear empties the queue. Reloading the page starts a fresh demo.
